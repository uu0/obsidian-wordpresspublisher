# 2.1.3-beta.2 — 发布可靠性修复

本次开发版本沿用现有插件，不增加摄影、读书或观影功能。发布到 dev，main 和正式 release 标签不变。

## 修复

- 发布任务固定源笔记；切换活动标签页不再改变回写目标。
- 原子检查源文件快照，拒绝覆盖并发编辑；图片链接替换在远端成功后执行，保留自定义 YAML 和正文。
- 发布窗口等待实际异步结果，再显示成功；关闭/取消登录、确认和发布窗口时结算等待状态。取消发布窗口不再隐式写入生成内容，需要保留时使用“保存”。
- 统一发布 HTML 清理；DOMPurify 异常时停止发布。Wiki 图片属性使用转义后的渲染，普通图片保留 alt 和尺寸。
- REST posts/pages 使用正确路由；更新支持清空摘要、标签和特色图片。此版本明确只支持 post/page，自定义内容类型留待后续协议开发。
- 正文图片缺失、图片上传失败、标签创建失败会停止发布；相对图片以源笔记路径解析，代码示例不上传或替换。
- 对已上传文件记录站点、文件类型、alt 和内容 hash，重试复用结果。POST 超时/连接中断不自动重发。
- 发请求前持久化发布意图，确认远端成功后记录 ID。若本地回写失败，再次发布只恢复 ID 与元数据，保留用户的新正文，不再重复 POST。
- 新增“Resolve uncertain publish / 核对发布结果”命令。对结果未知的文章/媒体，先在 WordPress 核对，再填写现有 ID，或明确确认没有生成。填写文章 ID 后只恢复绑定；当前正文需要再次发布才会同步。
- 分类/标签列表分页；标签搜索编码并精确匹配，不再取模糊搜索第一项。
- “不记住密码”清除旧密码/密文；密码输入隐藏；OAuth token 转为现有凭据密文格式。损坏的单个凭据不会阻止其余站点加载。
- 设置、缓存及恢复记录串行保存，减少互相覆盖；特色图缓存包含站点，远端特色图按当前选定站点读取。
- REST/XML-RPC 凭据连接要求 HTTPS，localhost 开发允许 HTTP。REST DEBUG 不再打印 Authorization。
- REST 与 AI 请求结束后清理超时定时器；dev 分支纳入 CI。

## 验证

本地 `npm run check` 包含 Jest、TypeScript 严格检查和生产打包。新增真实发布调用路径的回归测试，以及传输、UI 异步生命周期、凭据保存和并发存储测试。最终测试数量见本次提交/交付记录。

## 使用与边界

- 本版本保持 beta；尚未对真实 Obsidian 桌面/移动端和真实 WordPress 站点做端到端验收。
- 发布结果未知时，不自动假定失败。核对命令不删除 WordPress 资源。多站点笔记可用 blogName 指明要核对的站点。
- HTML 中仍存在未解析的本地图片（如未支持的复杂引用语法）时停止发布，改为普通内联图片引用后重试。
- 本次没有引入系统钥匙串或主密码。现有固定应用密钥派生方案仍只是本地混淆，能读取插件及配置的人可解密。不要将插件数据文件公开提交。
- 已上传资源的远端手工删除、跨设备同时发布、WordPress.com/XML-RPC 的完整协议覆盖及移动端图像兼容，还需下一阶段专门验证。
- 新恢复记录和密文格式应使用此版本读取；降级前备份插件 data.json。没有自动批量修改笔记。

## 后续项目边界

Obsidian 客户端继续在本仓库内模块化扩展，普通文章不依赖服务端插件。WordPress 的 sunyang-collection 单独建仓库，负责 CPT、结构化字段、权限和展示。客户端设置增加可选的云端插件连接与能力检测，内部拆出内容模型、发布用例、媒体适配器，不把所有逻辑继续放进发布弹窗。
